# 설계 노트

"왜 이렇게 만들었나"의 긴 이야기들. 기능 문서([화면과 기능](features.md))와 [구조](architecture.md)는 지금의 동작만 적고, 그렇게 된 사연 — 겪은 사고, 재 본 숫자, 버린 대안 — 은 여기에 둔다. 날짜는 그 일이 있었던 버전([CHANGELOG](../CHANGELOG.md))의 것이다.

## 설정 파일을 앱이 스스로 날리지 않게 한다

0.1.1(2026-09-21)과 0.1.14(2026-09-22). 지금의 규칙은 [구조 › 설정 파일](architecture.md#설정-파일-uijson).

**이 파일을 앱이 스스로 날리지 않게 한다.** `ui.json` 에는 계정 목록과 저장된 탭도 들어 있는데, 예전에는 세 가지 경로로 통째로 사라질 수 있었다. (1) 읽기가 실패하면 — 재부팅 직후 백신이나 동기화 프로그램이 파일을 잠깐 쥐고 있을 때 — "파일 없음"과 똑같이 빈 설정으로 취급했고, 곧이은 저장(창을 옮기기만 해도)이 그 빈 설정으로 전체를 덮어썼다. 이제 **있는데 못 읽은 파일**은 60ms 간격으로 8번 다시 읽고, 그래도 안 되면 읽힐 때까지 **아무것도 쓰지 않는다**. (2) 쓰기는 원자적이었지만 내구적이지 않았다: fsync 없는 rename 은 정전 뒤에 0 으로 채워진 파일을 남길 수 있다. 이제 rename 전에 fsync 한다. (3) 깨진 파일은 곧 빈 설정이었다. 이제 직전의 온전한 파일을 `ui.bak.json` 으로 남겨 두고, 깨졌을 때 그것을 읽는다(깨진 파일은 전처럼 `ui.corrupt.json` 으로). 그리고 목록은 잃었어도 **계정 폴더와 그 안의 로그인은 남아 있으므로**, 시작할 때 `~/.hamster-desk/profiles/acc-N` 가운데 목록에 없고 CLI 가 쓴 흔적(`.credentials.json`·`.claude.json`)이 있는 폴더를 목록에 되돌린다(`adoptOrphanProfiles`; 이름은 로그인 이메일의 앞부분). 일부러 지웠는데 파일이 잠겨 다 못 지운 폴더는 `.hamster-deleted` 표식이 있어 되살아나지 않고, 그때 다시 지운다.

(4) **두 프로세스가 한 파일을 나눠 쓴다.** 이 파일은 실행 모드를 가리지 않는 것이 목적이라 설치판과 `npm run dev`·캡처 실행이 같은 파일을 읽고 쓴다 — 그런데 각 프로세스는 파일을 켤 때 한 번 읽어 메모리에 들고, 저장할 때마다 **그 사본을 통째로** 되썼다. 둘이 같이 떠 있으면(설치판 안의 Claude Code 세션이 `HAMSTER_HOME` 없이 캡처 실행을 돌리는 것이 바로 그 경우다) 한쪽이 더한 최근 프로젝트·즐겨찾기는 다른 쪽이 창만 옮겨도 파일에서 사라졌고, 먼저 뜬 쪽을 껐다 켜면 — 앱 업데이트로 다시 뜨는 것도 포함해서 — 영영 사라졌다. 이제 쓰기 직전에 파일을 **다시 읽고**, 그 위에 이 프로세스가 바꾼 키만 얹는다(안 건드린 키는 파일 것이 이긴다). 목록(`recents`·`favs`)은 렌더러가 바꾸기 전의 값(`base`)을 같이 보내므로, 상대가 그 목록을 바꿔 두었으면 통째로 갈아 끼우는 대신 **이쪽이 더하고 뺀 것만** 상대의 목록에 적용한다 — 이쪽이 `×` 로 지운 것은 지워지고, 저쪽이 더한 것은 뒤에 남으며, 같은 폴더는 대소문자·끝 슬래시를 무시하고 하나로 본다(`src/sidebar/recent.ts` 의 `dirKey` 와 같은 규칙). 쓰려는 순간 파일이 안 읽히면 그때도 쓰지 않고 2초 뒤에 다시 시도한다(최대 5번; 종료 중이면 마지막 300ms 의 변경이 대가다). 캡처 실행은 아예 읽기 전용이다([구조](architecture.md#설정-파일-uijson)). 검증은 `scripts/unit/ui-store.test.ts` — 다른 프로세스 역할은 파일을 직접 써서 한다.

## 설치판 업데이트의 세 가지 사연

설치판이 어떻게 새 버전을 찾고 받는지는 [구조 › 설치판](architecture.md#설치판-github-releases-와-electron-updater).

### 설치는 절대 몰래 하지 않는다 (0.1.6, 2026-09-21)

**설치는 절대 몰래 하지 않는다**: 앱을 바꾸는 동안 실행 파일은 30초쯤 없어지는데, 보이지 않는 설치는 그사이 작업 표시줄 아이콘을 다시 누르게 만들고 — 그러면 "경로가 존재하지 않습니다"가 나오거나, 옛 exe 가 설치 프로그램 밑에서 켜져 설치가 깨진다. 그래서 앱을 끌 때 조용히 설치하는 것(`autoInstallOnAppQuit`)은 꺼 두었다.

### 릴리스 피드가 504 를 낸 밤 (0.1.10 → 0.1.11, 2026-09-22)

설치판은 먼저 릴리스 피드(`releases.atom`)에 묻고, 그것이 실패하면 `releases/latest/download/latest.yml` 에 묻는다. 두 번째 길이 생긴 계기: 0.1.10 이 나온 밤에 그 피드가 이 저장소와 electron/electron 양쪽에서 504 를 냈고(GitHub 상태 페이지는 정상이었다), 파일은 전부 멀쩡히 내려받을 수 있는데도 설치된 앱은 새 릴리스를 보지 못했다. 그래서 피드가 실패하면 `latest.yml` 로 갈아타고, 그래도 안 되면 20초·1분·3분 뒤에 다시 해 보며, `⋯` 메뉴의 `확인 실패` 아래에 이유를 적는다.

### 0.1.1~0.1.8 의 설치판은 스스로 업데이트하지 못한다 (0.1.9, 2026-09-21)

**0.1.1~0.1.8 의 설치판은 스스로 업데이트하지 못한다**: electron-updater 는 CommonJS 이고 `autoUpdater` 를 getter 로 내보내는데, 메인 번들은 `await import('electron-updater')` 를 진짜 동적 import 로 남긴다 — node 는 CommonJS 모듈에서 정적으로 보이는 이름만 꺼내 주므로 getter 로 정의된 `autoUpdater` 는 이름으로는 `undefined` 이고 `default`(= module.exports) 아래에만 있다. 그걸 이름으로 읽어서 모든 확인이 `Cannot set properties of undefined (setting 'autoDownload')` 로 실패했다(타입은 그 이름이 있다고 하므로 실행해 보기 전에는 알 수 없었다). 0.1.9 부터는 두 자리를 다 보고(`pickAutoUpdater`), 단위 테스트가 실제 패키지를 같은 방식으로 불러와 그 자리를 확인한다. 그 버전들을 깐 PC 는 **최신 설치 파일을 한 번 직접 받아 설치**해야 한다.

## electron-builder 의 자체 게시를 쓰지 않는 이유

0.1.1 → 0.1.2(2026-09-21). `scripts/release.ts` 가 하는 일은 [구조 › 릴리스 스크립트](architecture.md#릴리스-스크립트).

electron-builder 의 자체 게시 기능은 쓰지 않는다: 파일마다 업로드를 동시에 시작하고 각자 "릴리스가 없으면 만든다"를 해서, 0.1.1 때 같은 태그의 초안이 둘 생기고 `.blockmap` 만 든 쪽이 공개됐었다(그 자리에서 나머지 두 파일을 올려 바로잡음).

## 포터블 exe 를 버린 이유

패키지 빌드: `release/win-unpacked/Hamster Desk.exe`. 압축하지 않은 폴더 그대로다 — 단일 포터블 exe 는 켤 때마다 앱 전체(약 410MB)를 `%TEMP%` 에 풀고 끌 때 지워서 시작이 느렸다. 옮길 때는 `win-unpacked` 폴더째로 옮긴다.

## 새로 빌드한 뒤의 첫 실행만 느리다

부팅 순서는 [구조 › 부팅](architecture.md#부팅).

**새로 빌드한 뒤의 첫 실행만 느리다**(한동안 무반응이다가 로딩 화면도 없이 뜬다). 앱이 하는 일이 아니다 — 서명 없는 240MB exe 를 Windows 가 처음 실행할 때 백신이 읽는 시간이고, 그동안은 프로세스의 첫 줄도 돌기 전이라 로딩 화면을 그릴 코드가 없다. 같은 PC 에서 재 보면 서명 없는 86MB exe(node.exe 복사본에 바이트를 덧붙인 것)의 첫 실행이 0.57초, 두 번째가 0.05초다. 앱 쪽은 다 합쳐도 짧다: 복셀 월드 생성 33ms, 워처가 실제 세션의 이벤트 446개를 내는 데 14ms. 어디서 시간이 갔는지는 실행할 때마다 `~/.hamster-desk/boot.log` 에 한 줄씩 남는다(`electron/boot-log.ts`, 최근 50줄):

```
2026-09-21T06:40:01.123Z 0.1.0 2cd4682 packaged | os>main 9800 | ready +210 | window +35 | dom +480 | load +20 | booted +340 | total 10885ms
```

`os>main` 이 Windows 가 프로세스를 만든 때부터 `main.ts` 첫 줄까지, 즉 앱이 손댈 수 없는 구간이다. 그 뒤는 전부 앱이다(`booted` = 로딩 화면이 걷히는 때). 첫 실행이 느렸는데 모든 숫자가 작다면 프로세스가 생기기도 전에 막혀 있었다는 뜻이다. 줄이려면 폴더를 백신 검사 예외에 넣거나 exe 에 코드 서명을 해야 한다 — 둘 다 앱 밖의 일이다.

## 작업 표시줄 고정과 AUMID

0.1.1·0.1.6(2026-09-21). 지금의 규칙 한 줄은 [구조 › 작업 표시줄 고정](architecture.md#작업-표시줄-고정).

**작업 표시줄 고정**(`electron/shortcuts.ts`). 작업 표시줄은 고정된 바로가기와 창의 AUMID 가 같아야 한 버튼으로 합친다. 이 앱은 토스트 때문에 AUMID 를 직접 정하는데(`kr.amag.hamsterdesk`) 설치 프로그램이 없어 그 ID 를 바로가기에 적어 줄 주체가 없었다. 그래서 (1) 탐색기에서 exe 를 고정하면 ID 없는 바로가기가 되어, 거기서 켠 앱이 고정 버튼 옆에 **두 번째 버튼**으로 떴고, (2) Electron 이 토스트를 처음 띄울 때 스스로 만드는 `시작 메뉴\프로그램\Hamster Desk.lnk` 는 한 번 만들어지면 다시 보지 않아서, 예전 포터블이 풀리던 `%TEMP%` 폴더를 가리킨 채 남았다 — 실행 중인 창을 고정하면 Windows 가 **그 바로가기를 복사**하므로, 고정 버튼은 창과 합쳐지지만 **눌러도 아무것도 켜지지 않았다**. 패키지 빌드는 시작 2초 뒤 이 둘을 바로잡는다: 시작 메뉴 바로가기가 없으면 만들고, 시작 메뉴·작업 표시줄의 바로가기 가운데 "이 exe 를 켜는데 ID 가 없는 것"과 "ID 는 우리 것인데 exe 가 사라진 것"을 현재 exe + ID 로 고친다(`update` 라 Electron 이 넣어 둔 토스트 CLSID 는 그대로). 아직 존재하는 다른 복사본을 가리키는 바로가기와 남의 바로가기는 건드리지 않는다 — 단, 대상이 `%TEMP%` 안이면 파일이 남아 있어도 고친다(예전 포터블이 풀어 놓고 치우지 못한 찌꺼기이지 누구의 설치도 아니다). 고정은 **앱을 켠 뒤 작업 표시줄 버튼을 우클릭 → 작업 표시줄에 고정**, 또는 시작 메뉴의 Hamster Desk 에서 한다. 창에는 재실행 정보(`setAppDetails`: 이 exe·아이콘·ID)도 달려 있어, 실행 중인 창을 고정할 때 시작 메뉴 바로가기가 아직 낡았더라도 고정 버튼은 이 exe 를 켠다. **한계**: 앱을 한 번도 켜기 전에 exe 를 끌어다 고정한 버튼은 ID 없이 만들어지고, 탐색기는 고정 버튼의 ID 를 기억해 두기 때문에 나중에 바로가기를 고쳐도 탐색기를 다시 시작하기 전에는 버튼이 둘로 남는다 — 그 버튼은 한 번 고정 해제하고 위 방법으로 다시 고정한다. 설치 프로그램으로 깐 경우에는 처음부터 생기지 않는 문제다.

## 왜 Windows 토스트가 아닌가

알림 창 자체는 [기능 › 알림 창](features.md#알림-창).

이 PC 에서 토스트는 Windows 가 받았다고 답하고(Electron `show` 이벤트, 레지스트리 `Notifications\Settings\kr.amag.hamsterdesk` 의 `LastNotificationAddedTime` 갱신) 화면에는 안 그렸다. **방해 금지**(CloudStore 의 `quiethourssettings` 가 `Microsoft.QuietHoursProfile.PriorityOnly`; Windows 11 은 전체 화면 앱·디스플레이 복제 때 스스로 켠다)가 배너를 삼키고 알림 센터에만 쌓는데 앱에는 아무 말도 없어서, `failed` 로 갈아타던 배너 폴백도 돌지 않았다 — 작업표시줄만 깜빡였다. AUMID 세 변형(`none`·`app`·`exec`)을 돌려 봐도 셋 다 `shown` 이었다. 그래서 OS 토스트 경로와 `HAMSTER_NOTIFY_PROBE`·`HAMSTER_AUMID` 는 지웠고(AUMID 자체는 작업표시줄 묶음용으로 `electron/shortcuts.ts` 에 남는다), 앱 안 배너는 알림 창을 만들지 못했을 때(`failed`)의 폴백으로 8초 뜬다. 깜빡임은 어느 쪽이든 동작하므로 알림이 조용히 사라지는 일은 없다.

## "답을 기다린다"를 알아보는 두 길

0.1.12(2026-09-22). 알림이 언제 울리는지는 [기능 › 알림](features.md#알림).

**"답을 기다린다"는 두 곳에서 안다**(`electron/prompt.ts`). ① 터미널 화면 글자: 이스케이프와 공백을 지운 뒤 권한 요청·신뢰 확인·MCP 확인의 고정 문구를 찾고, **선택지형 질문**(AskUserQuestion)은 마지막 선택지 `N. Chat about this` 바로 밑에 `Enter to select · ↑/↓ to navigate · Esc to cancel`(질문이 여럿이면 `Tab/Arrow keys to navigate`)이 붙은 모양으로 찾는다 — 예전에는 `Enter to confirm` 만 찾아서 CLI 2.1.x 의 선택지 질문이 한 번도 걸리지 않았다. 문구 하나만으로는 찾지 않는다: 그 문구를 말하는 산문(대화·README)에도 걸린다. ② 트랜스크립트: `AskUserQuestion` 도구 호출이 기록되면(답을 기다리는 동안에도 기록된다) 그 세션이 도는 터미널이 질문 중이다. 화면 문구가 CLI 버전마다 바뀌어도 이쪽은 남는다. 다만 새 세션의 첫 질문은 CLI 가 ~20초 늦게 쓴다(실측). 둘이 같은 질문을 보면 한 번만 알린다(10초 안, 그사이 Enter/Esc 가 없으면 같은 것), 기록이 오기 전에 이미 답했으면(Enter/Esc) 알리지 않고, 60초보다 오래된 기록(따라잡기)은 무시한다.

## 5시간 창 자동 시작이 있는 이유

0.1.12(2026-09-22). 기능은 [기능 › 5시간 창 자동 시작](features.md#5시간-창-자동-시작).

구독의 5시간 창은 시계로 도는 게 아니라 **창이 끝난 뒤 첫 메시지**에서 시작한다. 밤새 쉬고 아침 10시에 처음 치면 창이 10시~15시가 되고, 오후에 몰아 쓰면 한참 남기고 한도에 걸린다. 그래서 켜 두면 창이 끝나고 1분 뒤 그 계정으로 짧은 메시지를 하나 보내 다음 창이 곧바로 시작되게 한다 — 창이 끊김 없이 이어진다.

## 멀티 에이전트: CLAUDE.md 에 상시 지시를 두는 이유

스위치와 방식은 [기능 › 멀티 에이전트](features.md#멀티-에이전트).

멀티 에이전트 스위치는 바에서 유일하게 터미널에 아무것도 치지 않는다. 하네스가 하는 방식대로 **상시 지시**를 시스템 층에 두는 것이다: 켜 두면 그 계정의 `CLAUDE.md` 끝에 표시된 블록 하나가 들어가고, Claude Code 가 세션을 시작할 때 이 파일을 읽어 시스템 프롬프트에 넣는다. **문안은 방식마다 한 줄**이다 — 사용자가 프롬프트 끝에 붙일 법한 한 문장 이상은 넣지 않는다. 보고 형식·테스트 규율·예외 조항까지 적어 두면 Claude 가 테스트와 보고를 과하게 했다.

## 모델 드롭다운의 별칭 표

0.1.14(2026-09-22). 드롭다운은 [기능 › 세션 컨트롤 바](features.md#세션-컨트롤-바).

모델 드롭다운의 `/model <alias>` 는 그 세션만 바꾸지 않고 `~/.claude/settings.json` 의 기본 모델을 덮어쓴다. 0.1.13 까지는 이 이유로 이름만 보여 줬는데, effort 가 이미 같은 일을 하고 있어 숨길 이유가 되지 못했다.

별칭 표는 CLI 2.1.278 바이너리에서 읽었다(`src/session/models.ts`): 받는 것은 `sonnet · opus · haiku · fable · best · sonnet[1m] · opus[1m] · fable[1m] · opusplan`. 셋은 일부러 뺐다 — `best` 는 등급 기본값(지금은 fable)이라 "기본"과 "fable"을 구분해 체크할 수 없고, `[1m]` 은 계정 자격을 CLI 가 확인해야 나오며, `opusplan` 은 모델이 아니라 모드(플랜 중 Opus, 그 외 Sonnet)라 CLI 가 실제 쓴 모델만 알려 주므로 체크를 정직하게 붙일 수 없다. 터미널에서 `/model opusplan` 은 그대로 된다.

## 탭 닫기가 Ctrl+W 가 아닌 이유

0.1.10(2026-09-22). 단축키 표는 [기능 › 터미널](features.md#터미널).

PSReadLine 과 Claude Code 입력줄이 둘 다 `Ctrl+W` 를 "앞 단어 지우기"로 쓴다. 문장을 고치다가 탭이(그리고 그 안의 세션이) 닫히면 안 되므로 `Ctrl+Shift+W` 다. 그런데 0.1.9 까지는 그 `Ctrl+W` 가 **창을 통째로 닫았다**: Electron 은 아무도 말하지 않으면 기본 메뉴를 깔고, 메뉴 바를 숨겨도(`autoHideMenuBar`) 그 단축키는 살아 있다 — `Ctrl+W` 닫기, `Ctrl+R` 새로고침(터미널이 전부 날아간다. 셸에서는 기록 검색이다), `Ctrl+±/0` 화면 배율(글꼴 단축키와 겹쳤다). 이 앱의 단축키는 전부 렌더러가 처리하므로 메인은 시작하자마자 `Menu.setApplicationMenu(null)` 로 기본 메뉴를 없앤다. Windows 에서 입력란의 복사·붙여넣기는 메뉴 없이도 된다. 메뉴에 있던 DevTools 는 개발 실행에서만 `F12`·`Ctrl+Shift+I` 로 남겨 두었다.

## 자동 카메라의 프레이밍

카메라와 자동 카메라의 동작은 [기능 › 카메라](features.md#카메라); 회귀 테스트는 [개발·검증 › 스튜디오 디자인 검증](development.md#스튜디오-디자인-검증).

- **말풍선 줄 수는 배율이 정하고, 여백은 딱 그 줄 수만큼만 잡는다.** 말풍선은 DOM 이라 배율이 낮아져도 글자가 작아지지 않는다 — 달라지는 건 *가독성* 이 아니라 *얼마나 장면을 덮느냐* 다. 그래서 `feedLines(배율)` 로 그릴 줄 수를 정한다: **≥340%·220% 4줄 · 150% 3줄 · 110% 2줄 · 80% 1줄 · 그 아래 0줄**. 필요한 여백 픽셀은 줄 수에 비례하지 배율과는 무관하므로 `frameHeadPad(높이, 줄수) = min(줄수 × 26 + 10, 높이의 18%)` 다.
- **`frameCamera` 는 2패스다.** ① 여백 0 으로 맞춰 "최대한 가까우면 얼마인가"(`s0`)를 구하고, 그 배율이 곧 그릴 줄 수다 ② 그만큼의 여백을 잡고 한 번만 다시 맞춘다. 여백을 잡으면 **멀어지기만** 하므로 줄 수는 줄어들 수만 있고(4줄용 여백이 3줄에 조금 남는 정도) 수렴 반복은 불필요하다 — 경계에 걸친 대상이 두 구간을 오가며 떠는 것보다 이 여유가 낫다. 단, 다시 맞춘 결과가 **0줄로 떨어지면** 여백이 아무것도 사 주지 못한 것이므로 ① 로 되돌린다(더 가깝고 한 줄은 보인다).
- 여백을 잡은 경우 피사체는 그 아래 띠의 한가운데에 놓이므로 구도가 살짝 **아래로 내려간다**. 실측(1280×520 책상, 괄호는 이번 작업 전): 둘 **169%**(156%, 3줄) · 사장 주변 넷 **117%**(104%, 2줄) · 아홉 **84%**(75%, 1줄) · 만석 13석 **81%**(75%, 1줄). 모든 인원수에서 전보다 가까워지고, 말풍선도 최소 한 줄은 보인다.
- 렌더 루프도 같은 `feedLines` 를 읽어 **최근 N줄만 그린다**(넘치는 옛 줄은 `display: none`). 그래서 "보여 주는 줄"과 "자리를 비워 둔 줄"이 어긋날 수 없다.
- **`autoFrameCamera` 는 지면이 아니라 "말풍선이 걸리는 점"을 기준으로 내려 잡는다.** `frameCamera` 의 여백은 햄스터 *발밑* 에서 재므로, 말풍선이 매달리는 `BUBBLE_H`(바닥 위 약 97: 의자 높이 + 앉은 머리 + 귀 끝 여유 + 20, **리그 상수에서 계산** 하므로 체형을 바꾸면 같이 움직인다)는 배율·뷰포트 높이마다 다른 픽셀 수가 된다. 책상 700px 에서는 넉넉했지만 앱 기본값 **420px 에서는 4줄이 화면 위로 잘렸다**. 그래서 ① 예전처럼 배율을 맞추고 ② 그 점을 투영해 **위로 쌓일 줄 수(`줄수 × 26 + 18`)가 `HEADER_PAD`(56, 스튜디오 헤더 띠) 아래로 내려올 때까지 지면을 팬** 하고(원근 때문에 한 번에 안 맞으므로 4회 수렴) ③ 그렇게 내려 가장 가까운 햄스터가 화면 아래로 빠지면 배율을 6% 씩 줄여 다시 시도한다(하한 75%, 6회). 둘 다 안 되면 **머리 쪽을 살린다** — 발이 잘린 햄스터는 말은 하지만, 말풍선이 잘린 햄스터는 아무 말도 못 한다. 머리·발 측정은 `FRAME_PAD` 를 도로 뺀 사각형(`frameSubject`)에서 하므로, 아무도 없는 여백 모서리 때문에 하늘을 비우는 일은 없다.
- 한 마리만 있을 때는 같은 함수를 상한 300% 로 불러 책상 근접을 유지한다(`⌂` 도 자동을 켜는 것이므로 같은 구도로 간다). 실측(1280 폭): 책상 높이 **420·520·700 어디서도 배율 300%, 말풍선 4줄이 헤더 아래에 전부 들어온다**(`work/shot-feed-420.png`·`shot-feed-700.png`). `동료 위치 찾기`·더블클릭은 여전히 `focusCamera` 의 250% 수동 구도다.

## 리그는 게임 문법, 체형은 햄스터

스킨·넥타이·정장은 [기능 › 햄스터](features.md#햄스터).

`src/desk/vox/hamster.ts`. 조립 문법은 `imjustawall_boxel` 의 `buildCat(kind, material, paint, biped = true)` 그대로다 — 네발 좌표로 만든 몸통을 통째로 세우고(`rotation.x = -π/2`) 등·머리 방향이 저절로 맞으며, 팔 2·다리 2 는 게임의 네 다리처럼 한 지오메트리를 공유하고 머리는 따로 도는 그룹이다. **지오메트리는 고양이가 아니라 설치류**다(예전엔 게임 고양이를 좌표까지 1:1 로 옮겨서 "너무 고양이 같다"는 말을 들었다): 몸통은 짧고 두껍게 `28×22×34`(폭×앞뒤×높이), 다리는 `8×11×8` + 발 `8.4×3×8.4` 로 짧게, 꼬리는 긴 기둥 대신 엉덩이의 **뭉툭한 뭉치** 하나, 귀는 작고 둥근 2단(아래 `7×5×6` + 위 캡 `5×2.5×4.5` + 분홍 속귀)이다. 리그 상수는 세 가지 불변식에서 나온다 — 발이 바닥에 닿으므로 `LEG_Y 11.6`(다리 지오메트리 최저점 −11.6), 세운 몸통이 y 11.5~45.5 이므로 `BODY_Y 30.5`(월드 y = `BODY_Y` + 박스의 authoring z), 머리 밑면이 몸통 윗면을 4 파고들므로 `HEAD_Y 42.5`. 어깨는 `ARM_Y 42`·x ±17(몸통 옆면 ±14 에 1 겹침), `TAIL_Y 13`, 귀 끝은 `HAMSTER_H = HEAD_Y + 21.25`(말풍선·글리프 앵커). 앉기/타이핑/읽기/생각/통화/인사/잠 포즈는 절차적으로 만든다(`poseRig`). 팔레트는 털·등줄무늬만 모델 스킨이 정하고 배·눈(`0x252a33`)·코(`0xd97a8a`)·속귀는 고정색이다. 목도리는 없고 **배 앞에 작은 넥타이**(매듭·몸통·끝 세 상자, 가슴 패널 앞 1.1 에 떠서 겹면 없음)가 붙는데 그 색이 에이전트 종류(`tintFor`)다. 머리 악세서리(왕관·안경·헤드폰·잎)는 둥근 귀를 피해 두개골 앞쪽(z ≥ 4)에 얹히고, 옆으로 나온 것(헤드폰 컵·안경 템플)은 두개골 옆면 x ±11 을 0.4 물어 뜨지 않는다. 다리가 짧아진 만큼 앉은 오프셋(`SEAT_TOP − 1`)과 보폭(`0.5`)을 다시 잡아, 앉으면 머리와 팔이 여전히 상판 위로 올라오고 걸을 때 다리가 벌어져 보이지 않는다.

## 말풍선 컨테이너를 줄마다 갈아 끼우지 않는 이유

말풍선 피드의 동작은 [기능 › 말풍선 피드](features.md#말풍선-피드).

피드 **컨테이너**는 햄스터당 하나(`key = feed:<세션>:<햄스터>`)로 유지하고, 안의 줄만 `FeedItem.id` 를 key 로 마운트/언마운트한다. 컨테이너를 줄마다 갈아 끼우면 렌더 루프가 위치·투명도를 쓰는 `feeds` 맵에서 옛 요소의 ref 정리가 새 요소 등록 뒤에 실행될 수 있고, 그러면 새 말풍선이 마운트 시의 `opacity: 0` 에 갇혀 안 보였다. ref 정리는 자기 자신이 등록돼 있을 때만 맵에서 지운다. 회귀 케이스는 `test:office:ui` 에 있다(두 문장 → 줄 2개·마지막 문장이 맨 아래·opacity 1, 같은 활동 3번 → 줄 1개 + `×3`, 수명이 지나면 사라짐, 줄 클릭 = 그 줄만 제거).
